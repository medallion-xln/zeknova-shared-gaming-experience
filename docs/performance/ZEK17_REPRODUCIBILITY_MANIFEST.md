## Ownership trace

1. The compatibility bundle embeds its own complete Three.js runtime and owns the live renderer, scene, animation clock, and core gameplay object classes.
2. `assets/vendor/three.module.min.js` is a second browser module owner. The model runtime and environment runtime share this URL/module identity.
3. `src/runtime-reconstructed/model/model-runtime.js` creates one KTX2 loader for animated player, resident, enemy, and boss GLBs.
4. `assets/environment-runtime.js` creates a second KTX2 loader for environment GLBs.
5. Both KTX2 loaders use `./assets/vendor/basis/`, but they must detect support against their consumer renderer. That renderer is owned by the embedded compatibility Three instance, while their classes come from the vendored instance.
6. The deprecated Clock is instantiated inside the protected compatibility runtime.

## Safe-consolidation decision

`SAFE_TO_CONSOLIDATE=false` in the current architecture. The compatibility bundle does not export its Three namespace, renderer-compatible KTX2 singleton, or clock owner. The model runtime is protected by an exact-byte reconstruction contract. Replacing imports or sharing loader state would change protected generated bytes and cross incompatible Three class ownership.

The repeated high-fidelity actors are independently animated skinned meshes. Their source runtime exposes no instanced-skinned or batched-rig facility. Material or geometry interning after load is unsafe because palettes, weapons, hit reactions, skeleton bindings, and disposal are independently mutated.

## Matched-scene blocker

The repository has no deterministic six-scene fixture that fixes mission, camera, player position, residents, enemies, boss phase, streaming completion, and sample window. ZEK-16's live captures are not matched before/after fixtures. Per ZEK-17's stop rule, no batching optimization or reduction claim was made before those matched baselines existed.

Highest-leverage next step: create reconstructible scene fixtures plus a canonical exported renderer/model-loader boundary, then consolidate loaders and implement distant static/impostor representations at model creation time.
