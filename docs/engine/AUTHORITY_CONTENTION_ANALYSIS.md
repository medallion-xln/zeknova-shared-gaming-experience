# Authority and contention analysis — ZGE-09

## Measured bottleneck and chosen changes

The instrumented ZGE-08 command architecture held `BEGIN IMMEDIATE` over runtime evaluation. Its apparent worker queue peak of one concealed upstream SQLite contention. A 64-command-per-row 1/2/4/8/16-client probe found that rate-limit accounting itself was the dominant wait at eight clients: quota p95 352.34 ms versus gameplay lock p95 0.021 ms, IPC p95 11.84 ms and gameplay transaction p95 14.00 ms. At sixteen clients both quota and the gameplay lock contributed (250.12 / 64.81 ms p95). See [latency breakdown](COMMAND_LATENCY_BREAKDOWN.md) and the original raw traces; these are short diagnostic samples, not population limits.

The implementation therefore batches the same quota scopes into one short atomic SQL transaction, rather than spending multiple autocommits on deletion/increment/read. Existing per-IP and principal limits remain unchanged. Valid authenticated mutation intents enter a bounded local coordinator before quota writes, reducing contention from repeat actors ahead of other admitted actors. Authenticated validation/admission failures still consume the unchanged quota exactly once via the rejection path; they cannot bypass accounting by returning early. Rejected admission creates no gameplay receipt and never runs a candidate; retry retains the same logical command ID.

The coordinator admits at most sixteen active/queued mutation intents, two per actor, and class ceilings of eight movement or construction and four session-control intents. It rotates actors and preserves each actor's FIFO order; it does not coalesce or discard distinct authoritative commands. Resources and mission events remain atomic construction effects, not invented public grant/reward routes. State reads and history pages have separate read paths and existing quotas/page bounds. The private coordinator is scheduling metadata, not authority: a stable lock inode plus atomic pending-file publication survives publisher SIGKILL, dead/future-monotonic PID records are cleaned, and SQL serialization/fencing still protects every commit.

Fairness is among admitted authenticated commands. A single-thread PHP listener's accept queue, HTTP parsing, invalid-identity traffic and host CPU can still delay entry to that coordinator. This is not a WAN/DDoS starvation guarantee or equal construction success: clients with stale shared revisions must receive conflicts. Tests prove another admitted actor runs before a continuously repeated actor, class/per-actor overload is rejected, timeout/disconnect/restart leaves original intent retryable, and scheduling metadata remains bounded/private after killed publishers.

## Why candidate execution remains inside the write transaction

An optimistic read → candidate → short commit design was evaluated and not adopted. Checking only world revision is insufficient: rejected commands still advance durable cursor/receipt history, actor movement uses personal revisions, and membership/connection/session/fence state can change independently. A valid commit would have to prove the entire relevant snapshot/cursor/inventory/occupancy/player/claim state and current permission/temporal rules remained identical, or recompute safely. Future live economy/cooldown writers are not fully ported. No partial revalidation was substituted for the existing invariant boundary.

Commands retain `BEGIN IMMEDIATE`, current authentication and connection checks, sealed snapshot, durable receipt lookup, current roster, shared/personal revision validation, terrain/occupancy/cost evaluation, generation checks before publication and before COMMIT, and atomic events/claims/receipt/snapshot/checkpoint writes. A failed candidate or SQL write leaves no partial cost, XP, building or reward. A successful client acknowledgment still means committed SQL state; transport loss requires the same receipt lookup on retry.

Read-only world verification now uses a consistent `BEGIN` WAL snapshot, commits before projection IPC, and checks fresh authorization/connection state before response. It avoids reserving the gameplay writer merely to verify state. Quota accounting and occasional connection last-seen refresh remain metadata writes. A query may return a verified earlier revision while a concurrent command commits; the client publishes monotonic validated replicas. Historical `sqlite-commit` acknowledgment wording is retained for protocol compatibility; a read is not a new gameplay mutation.

## Safety evidence

The full engine suite retains pre/post-COMMIT death, database/claim-write failure, competing lease, expiry/revocation, duplicate/outbox and actor/team claim invariants. New tests add actual queued disconnect + worker deadline/restart, fresh revocation while read projection is in flight, batched quota limits across gateways, fair admission, crash-safe coordinator publication and prior-boot timestamp cleanup. Managed service database identity guards prevent missing/substituted files from being initialized as fresh worlds. There is one durable SQL writer at a time and one fenced world executor per world; no optimistic command success or live authority transfer was introduced.
