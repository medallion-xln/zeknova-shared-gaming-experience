# Editor memory and ownership observations

Studio uses one renderer/control pair for its page and replaces authoring/simulation engines separately. Each active scene has two subscriptions: kernel publication and Studio view update. Project close clears scene listeners, unsubscribes the old project observer, disposes systems/plugins and then releases shared assets/presentation. A new public test proves plugin cleanup runs before asset disposal and concurrent repeated dispose is idempotent. Trusted lifecycle calls should be awaited/serialized.

Viewport meshes share primitive geometry; removed/replaced objects release owned materials. Proposal wireframe materials are cleared on review/project changes. Transform/Orbit controls are disposed with the page, along with their listeners/helper resources. Project switching reuses the page renderer; full page close disposes it. Simulation reset disposes its separate kernel/systems and cannot alter authoring history. Collapsed hierarchy/error state clears between projects.

The realistic session performs16 project switches per backend, collecting explicit GC samples only between diagnostic steps through Chrome CDP. Four snapshots per backend observe exactly two scene listeners, zero asset references/pending loads and stable45 renderer geometries, including the actual transform-control helper geometry. Initial measured used-heap sequences were about8.38→8.46MiB on WebGPU and8.45→8.52MiB on WebGL; final raw runs are authoritative in the manifest. The tested bound allows4MiB growth to avoid treating normal browser compilation variance as a deterministic leak.

These are observed bounded project-switch/scene-replacement results, not proof of no possible leak. Browser-internal caches, GPU driver residency, long-lived histories, arbitrary model loaders and untrusted plugins are not fully covered. Drafts/assets intentionally persisted in browser storage are distinct from retained live scene objects and remain subject to browser quota. AssetService caches are bounded per project and released at close; no broader legacy Three/GLTF lifecycle problem is declared solved.

Separate world-evaluator heap snapshots and sustained service metrics are documented in OPERATIONAL_RELIABILITY_ZGE_11.md. Forced GC is confined to isolated diagnostics and browser test checkpoints; it is never added to the active multiplayer request path.
