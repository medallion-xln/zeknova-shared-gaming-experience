# Isolated V4 forward and rollback paths — ZGE-07

The ZGE-06 lossless read-only projection remains unchanged. `V4ConstructionMigration.js` adds a separate versioned editable construction branch, inverse V4 export and an atomic-store handoff. This certifies an isolated data boundary, not execution of the historical campaign/aid/utility/health game in the new runtime.

`prepareV4ConstructionMigration` preserves the original V4 save and its canonical provenance, derives a world owned by `isolated-v4-branch`, and can repeat-import its own exported construction extension. `validateV4ConstructionMigration` enforces original provenance, immutable identity fields, matching world identity/authority, monotonic world/inventory revisions, valid transforms/progress, agreeing mission/boss reward records and normal world/building/occupancy schema constraints. An edited branch must advance revision; changed balances must advance inventory revision. Imported extension state is copied independently of the original, so editing a cloned branch cannot silently change its preserved source.

`exportV4ConstructionMigration` writes resources, buildings, player pose/XP/rank, mission/reward records and explicit engine state into a synthetic V4 envelope. Unknown top-level, user and building fields survive; unknown extension schemas remain untouched. The known extension retains unknown members while its XP/rank fields update. Private revision metadata never regresses when a shared revision is lower. Existing arbitrary persistence fields remain preserved; this adapter does not reuse them to send a production save. A real legacy transport would still require a fresh operation identity and game-specific revision negotiation.

The `zgeConstruction` extension contains world/revision/schema and complete source world state, including engine event/progress metadata. A conflicting unknown construction extension or a mismatch between its state and legacy projection is rejected. Player/team identifiers remain bound to the source; the legacy world's ID derives from the saved team and any other legacy identifiers remain in the original envelope.

`rollbackV4ConstructionMigration` returns the exact original JSON data. `commitV4ConstructionMigration` validates before invoking an explicitly supplied compare-and-swap store; no unsafe read/write fallback exists. The committed record contains both original and forward save. Interrupted and stale CAS fixtures preserve the prior record. This is not permission for a live world rewind or a production database migration.

Nine ZGE-07 persistence/client tests include known, absent and old extensions; forward edits/reimport/rollback; changed ranks and boss claims; incompatible branches/identity/world/revisions; interrupted/stale atomic writes; malformed replica pages/snapshots, revision regression, in-flight disconnect and rapid out-of-order connection completion. Earlier ZGE-06 migration/provenance tests remain passing. All data is synthetic.

Full live execution migration stays **UNCERTIFIED**: historical utility/health/catalog, personal/team rewards, campaign/rank effects, aid benefit semantics, every writer lease, live save/network routing and reproducible original game build are still required.
