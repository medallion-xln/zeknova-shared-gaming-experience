# Studio world interactions

Studio keeps its dark neutral desktop layout, resizable scene/inspector panels, visible focus, readable controls and high viewport area. Functional World/Simulate/Render workspaces remain; no empty Logic tab is added. The new viewport toolbar exposes move/rotate/scale, world/local space, grid, snapping increments, focus/reset and perspective/orthographic projection.

The host injects its single Three namespace plus Three OrbitControls and TransformControls. The SDK adapter imports no Three copy. Left background drag orbits, right drag pans and wheel zooms; Focus/F targets selection and Reset restores the standard view. Orthographic projection is useful for planar alignment. Screen-coordinate picking refreshes camera/projection matrices after viewport resizing.

All X/Y/Z translation handles manipulate data; rotation and scale handles use actual Three interaction geometry. TransformControls scales handles with camera distance and manages local/world math. Scaling follows Three's local-axis convention. During object manipulation OrbitControls is disabled. Pointer motion changes only mesh presentation and temporary editor state; release commits one Scene transaction. Escape/pointer cancellation restores the starting transform without a revision. Movement after Escape continues restoring the canceled pose until release. Numeric controls provide keyboard alternatives. Snap values must be finite and positive; rotation snap input is degrees, while stored Euler values are radians.

Hierarchy supports search, collapsible groups/children, rename, duplicate, context-menu actions, hidden/locked states and parent references. Parent transforms apply through Three presentation nesting; numeric transforms are local to the parent. General physics inheritance is not implied; project rules must handle parent-local coordinates explicitly. Single-selection editing is certified. Multi-selection is intentionally absent until transaction/interaction policy is designed.

Deletion of a subtree requests confirmation and uses one atomic batch. Other dangling component references reject deletion with an actionable error. Generated duplicate IDs remain distinct. Hidden/locked ancestors cannot be picked/manipulated; inspector controls reflect locking. The hierarchy preserves visual selection and makes hidden/locked state explicit. Search and group state are editor presentation, not multiplayer state.

Physical Chrome tests cover axes, rotation, scale, local/world switching, snapping, exact Escape rollback, no camera motion during gizmo drag, camera orbit/pan/zoom/focus/reset, projection switching, resized picking, hierarchy/context actions, reflected editing and undo/redo on WebGPU and WebGL. This is a desktop toolkit foundation, not a claim of every professional DCC feature or mobile authoring support.
