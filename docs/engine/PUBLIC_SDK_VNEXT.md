# SDK preview 11: compatibility and public package

`@zge/sdk` is now `0.1.0-preview.11`, with packaged declarations for both `@zge/sdk` and `@zge/sdk/three`. Runtime Node support is explicitly22+ for the tested platform/Web Crypto contract; modern browser presentation uses host Three0.185.0. This is a documented preview transition, not a frozen1.0 API or a public registry release.

Existing v1 project input and v1 scene serialization remain accepted. `migrateProject` detaches and upgrades a v1 project to `zge.sdk.project.v2`, adds SDK compatibility, declarative component definitions, metadata and migration provenance. `parseProject` validates JSON and migration. V2 SDK major/minimum-preview checks reject unknown future requirements. Scenes remain `zge.sdk.scene.v1`; no invented pre-v1 format, original-game save or V4 migration is claimed. Negative zero normalizes to JSON zero; no-op transactions ignore object-key ordering and do not create history/revisions. These preview11 behaviors have explicit compatibility tests.

The public surface adds `createProject`, `parseProject`, `migrateProject`, `SDKError`, `componentSchemas`, declarative `registerComponent`, `editProperties`, `exportProject`, `importAsset`, `assetReferences`, prefab creation/status/overrides, rename/duplicate, diagnostics and data-only rules. Existing entrypoints, function-validator registration, manual lifecycle, events, assets, plugins, Scene operations and proposal review continue to work. Eleven original SDK tests remain intact, with six additional cases covering evolution, reflection/privacy, hierarchy/history, portable assets/prefabs and rejected executable content and plugin-before-asset disposal.

Declarations are maintained alongside public source, emitted to `dist` by the deterministic build and included in npm pack. A clean external TypeScript6.0.3 consumer checks both public entrypoints with strict settings and negative type assertions. The public declaration avoids private package paths. Host Three/control namespaces are deliberately structurally injected because this SDK does not own another Three runtime. Runtime data remains schema-validated; TypeScript alone is not validation.

Stable error codes include VALIDATION, COMPONENT_VALIDATION, PRECONDITION, REVISION_CONFLICT, DISPOSED, PROJECT_PARSE, PROJECT_VERSION, SDK_VERSION, COMPONENT_SCHEMA, OPERATION_UNSUPPORTED, ASSET_SIZE and ASSET_PARSE. Each SDKError carries code/message and optional path. Trusted custom validators/plugins can have their own errors; code running with direct Scene access is trusted. UI errors surface without partially publishing failed edits.

`engine.project` is initial metadata; `exportProject()` is current portable authoring truth. Function validator code and arbitrary plugin implementations are not serialized. Use declarative component definitions for portable validation; trusted hosts must explicitly register custom code. Studio refuses simulation when a declared plugin implementation is unavailable. Supported data-only move/collect/goal rules run through `installProjectRules`, never eval or an imported script URL.

Build with `npm run build:sdk`, pack with `npm pack ./packages/sdk`, and see the complete install/authoring/system/asset/prefab/simulation/export example in `packages/sdk/README.md`. `scripts/zge11-docs-check.mjs` executes that example. The external consumer exercises both runtime and TypeScript declarations after packed installation. Production, remote authority and original game migration are unchanged gates.
