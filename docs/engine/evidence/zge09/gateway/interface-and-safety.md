# Gateway ZGE-09 implementation facts

Response `metrics.schema = zge.command-metrics.v1` on supervised world and event-history routes. `worldId`, own `commandId`, command class, SHA256 of world/actor/logical ID as stable `transactionId`, generation. No credential/header values. Stages are monotonic PHP handler spans in milliseconds; absent stages zero. `transactionMs` is inclusive BEGIN-to-COMMIT (or rollback-error observation), overlapping the contained individual stages. Runtime queueWaitMs/evaluationMs are private supervisor/child monotonic durations summed over calls. PHP `ipc` includes serialization, socket transit, worker queue/evaluation and reply parsing. `totalMs` starts after PHP includes/handler entry and excludes the webserver accept queue. `upstreamQueueMs=null` explicitly avoids inventing an upstream measurement. `responseSerialization` measures a payload encode probe; final metric-enriched encode + network transport is part of client acknowledgment, not falsely attributed to the worker.

Client optional `onMetrics` receives immutable `zge.client-command-metrics.v1` only after full reply validation and replica publication. It includes httpAcknowledgmentMs, reconciliationMs, totalMs, generation and the server metrics. `lastMetrics` is bounded one-record storage. Observer failure cannot alter acknowledgment. It contains no token. Client clocks and server clocks are not subtracted across processes.

Mutation pipeline remains: trusted auth/validation, bounded fair admission, one short quota metadata transaction, ensure worker, BEGIN IMMEDIATE, current permission/connection/fence + complete sealed state verification + receipt lookup, candidate IPC, fence, all world/events/claims/receipt/checkpoint writes, current auth + fence, COMMIT. Admission permit releases after COMMIT, before rendering/projection work. SQL remains sole durable authority; no optimistic candidate commit was adopted. Admission corruption/failure fails closed. Concurrent bypassing older gateways still serialize through SQLite and every original invariant; admission does not replace authority.

Admission uses bounded owner-private JSON, a stable private `.lock` inode and atomic fixed `.pending` rename in the isolated DB directory. Actual publisher SIGKILL both after pending truncation and before rename preserves the old complete metadata; a subsequent request overwrites interrupted pending content. The future-monotonic timestamp from an earlier boot is rejected even when a stale PID is now live. At most16 queued+active perworld,2 perauthenticated actor; movement8, construction8, session-control4. There is one active mutation admission permit. Round robin actors with FIFO within actor. Default admission wait2sec; overflow/deadline yields429 and no gameplay receipt. No command coalescing. Dead PID/30sec stale metadata cleanup, shutdown release. Bounded metadata is not durability-critical. Fairness is among requests reaching authenticated admission: upstream PHP connection queues, authentication work, read traffic and quota writes can still affect end-to-end fairness. This is not a general network DoS guarantee.

Resource and mission effects remain in the same construction transaction; no invented standalone HTTP commands. Read-only state and history have separate paths/page limits and retain authorization/quota checks. State verification uses BEGIN read transaction, consistent snapshot seals/archive/checkpoints, COMMIT before projection IPC; final authorization/connection recheck runs outside the old transaction. History likewise avoids connection UPDATE inside its read transaction and freshly revalidates after COMMIT. Read last_seen refresh is at most once/minute outside the old transaction, preserving24h cleanup semantics. Quota writes remain; reads are not claimed to do zero writes. Existing sqlite-commit acknowledgment shape is retained for wire compatibility; read replies mean verified consistent SQL snapshots, not new gameplay mutation commits.

Quota optimization preserves600/IP/min and configured8..600/principal/min (default240). It batches one cleanup and scope UPSERT RETURNING counts inside one short SQLite transaction, committing counters even on429. Initial invalid sessions still count against IP. Early forbidden/invalid/admission-rejected requests cannot execute and may be rejected before quota accounting; rejection is stricter than permission to mutate. No normal quota was raised. SQLite RETURNING requires3.35+ (the captured environment supports it).

Tests: nine server gateway/admission tests, one client metrics test (10/10 final). Existing eleven08gateway tests pass. Initial new-test attempt failures were an expected killed subprocess promise not consumed by test harness and an assertion using wrong existing replay result key (`matches` instead of `deterministic`); both corrected without relaxing runtime assertions. Raw initial + final logs retained.
