# Studio UX and realistic session certificate

The WebGPU/WebGL Chrome script executes complete editing sessions rather than only isolated DOM controls. It physically drags X/Y/Z, rotates/scales, changes local/world space, snaps, cancels a drag with Escape, checks camera isolation, undoes/redoes, orbits/pans/zooms/focuses/resets, switches projection and resizes before picking again. It then searches/edits hierarchy, toggles visibility/locking, uses a context menu, renames/duplicates/deletes, imports/drops an asset, creates/overrides a prefab, exports/reopens in a fresh browser context, edits external custom component properties, simulates and runs the exported project independently.

Keyboard paths include labeled numeric alternatives, visible focus, shortcuts, focusable panel separators with arrow-key resizing, context actions, F focus and Escape cancellation. Editable form targets do not consume game shortcuts. Reflected read-only/private fields are disabled or omitted; errors appear in a polite status region without partial mutation. Existing source/legacy browser cases and all prior golden assertions remain active.

Minimum supported desktop layout is1000×700 CSS pixels;1280/1440/1600 desktop widths and viewport resizing are exercised across the new and retained browser checks. High-contrast neutral surfaces, CSS theme variables, native controls and independent panel scrolling remain. Text scaling/assistive technology coverage is a functional review, not a WCAG conformance or full screen-reader audit; mobile and very small layouts are unsupported. Camera/gizmo controls require the injected Three addons; they are not decorative stand-ins.

Save status compares current complete project content to the saved fingerprint, so no-op edits do not falsely dirty the project. Export is explicit and separate from browser save. Project switching first preserves an unsaved browser-local draft; Recover draft is available when reopening that project. Storage failures abort switching through the standard error path, retaining the current scene. Portable export remains the reliable cross-environment handoff. Project open validates a replacement before disposing the current engine.

Retained initial failures: a collapsed prefab section needed a real user expansion in the test; signed-zero export mismatch required canonical JSON normalization; the external example used the wrong addon module export; the first clean-build harness accidentally passed declaration files to Node's test runner instead of the TypeScript checker. No regression assertions were weakened. Final manifest identifies the passing artifacts.

Bounded classifications are separate: SDK, external consumer, visual Studio, portability, editor memory, gameplay regression and staging operations. This is local developer usability evidence by an agent, not an independent human study, full DCC suite or public production certification.
