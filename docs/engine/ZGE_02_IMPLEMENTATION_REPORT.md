## Priority 2 — Rendering and model-runtime consolidation — IMPL + AUTO + BROWSER
**Root causes traced**
1. Six module instances of `assets/model-runtime-c96327ba.js`: the bundle dynamically imports it under six different `?v=` cache-busters (`animation-audit1`, `enemy-roster9/10`, `quat-fix1`, `resident-population8`, `rifle-brace1`) and `environment-runtime.js?v=wetlands-village2`; the browser keys module instances by resolved URL including the query, so each variant got its own `GLTFLoader`, `KTX2Loader`, transcoder worker pool and serial queue.
2. No GLB cache: every loader instance fetches independently; the bundle re-requests enemy models per spawn.
3. Two Three.js instances: the bundle inlines r185 while `model-runtime-c96327ba.js`, `environment-runtime.js` and `model-runtime.js` import `./vendor/three.module.min.js`. The inlined copy exports nothing, so the vendor copy cannot be aliased to it without editing the bundle — **not fixed in ZGE-02 by design** (invasive bundle edit; needs the reproducible build that does not exist).

**Changes**
- `index.html` import map (generated by `packages/assets/src/importMap.js`, drift-guarded by a test that re-scans the bundle): all seven `?v=` variants → one canonical module each.
- `packages/assets`: `AssetRequestCache` (fetch-boundary, GLB/KTX2/WASM, in-flight coalescing, byte-budgeted LRU, default 64 MB); `LoaderWatchdog` (patches the shared vendor `GLTFLoader.prototype.load` to track every load, settle both paths, report stalls ≥15 s with KTX2/meshopt/worker diagnostics); `installWorkerObserver` (live worker counts, error events). Installed by the new pre-runtime director `asset-consolidation` before the bundle loads. 5 Node tests.

**GLTF hang investigation (DERIVED + BROWSER)** — the readiness chain `player.hqReady → loadAOEnvironment → environmentReady → enemy loaders` blocks forever if one `loadAsync` never settles; the only non-settling path in the loader stack is a KTX2 transcode whose worker dies without posting (worker crash → promise never resolves; GLTFLoader cannot time it out). With 4–7 loader instances each spawning a pool of 4 workers holding a 2 MB transcoder copy, worker pressure is the leading hypothesis; it is reduced from ≤16 to 8 workers by the import map. `KTX2Loader.detectSupport` on WebGPU calls `renderer.hasFeature`, which throws before device init — a rejection, not a hang. The hang did not reproduce in 9 launches this session (0 stalls). The watchdog now converts any future hang into a stall report with the URL and worker state; the timeouts remain as the last line of defence (acceptance gate 7).
