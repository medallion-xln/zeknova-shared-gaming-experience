# External developer workflow: Signal Garden

The consumer lives outside the monorepo at `/Users/dwaynecampbell/Desktop/zge11-signal-garden`. It installs a packed public `@zge/sdk` plus pinned Three; TypeScript is a consumer dev dependency. A second fresh temporary consumer install repeats offline clean dependency installation, game-specific tests and strict TypeScript checks. Its artifact/source hashes are in the final manifest.

Signal Garden is a small independent world with a gardener, signal seed, garden bed and beacon objective. Its own project JSON defines custom gardener/goal schemas, including number, boolean, string, enum, vector, asset and entity fields. Public data-only rules register movement, resource collection and objective completion. The external host uses only public package exports and its own code; it has no monorepo/private path or ZekNova content import.

The workflow is tested end to end: install public package, create scene/custom component/rules, load a verified palette asset, open JSON in Studio, inspect/edit custom properties, simulate without changing authoring data, export the complete edited project, import it in the independent host, run collection/objective and save/restore. Project-specific Node tests exercise the rules and public asset/persistence API. TypeScript checks both core and renderer entries, plus negative renderer/vector type assertions.

The external loopback server is GET-only and restricted to its workspace; there is no write API or production deployment. Public runtime dependencies are contained in the packed SDK or explicitly installed peer Three. A provenance/licensing manifest exists for the small self-authored JSON palette. This integration was carried out by this agent from the public docs, not a separate human usability study or a production-ready second commercial game.

Recorded friction: the initial consumer browser example mistakenly imported TransformControls from OrbitControls' file; browser module validation caught it and separate documented imports fixed it. Complete-project export initially exposed signed-zero normalization; the SDK now normalizes JSON consistently. Function validators/plugins cannot be serialized automatically; portable schemas and explicit trusted-host registration are documented. Assets with unknown redistribution rights remain unknown. These issues and failed attempts are retained rather than hidden behind private imports.
